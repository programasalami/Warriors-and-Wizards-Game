# Warriors & Wizards - browser client (WebAssembly + WebGL2)

The same game client as the desktop `.exe`, compiled to WebAssembly so it runs in a web page. **The desktop sources are not modified**:
`web/web.csproj` links them in place and swaps the native parts (OpenTK window / OpenGL / OpenAL, raw TCP sockets, stb image) for browser versions.

```
WebClient/
  web/                 the WebAssembly project
    web.csproj         compiles Alloy.Common / ContentReader / Engine / UiLib / AlloyClient / Common.Protocol from ../../AlloyClient + ../../Shared
    shim/              browser replacements: GL.cs (OpenTK GL -> WebGL2 via gl.js), Platform.cs (window/input events), GameWindow.cs (rAF loop),
                       StorageBuffer.cs (SSBO -> data texture), Audio.cs, WebClient.cs (WebSocket instead of TCP), ReFuel.cs (managed PNG decode), Enums.g.cs
    WebHost.cs         entry point + JS<->C# bridge (input events, content download, saved login/settings in localStorage)
    shaders/           GLSL ES 3.00 ports of the game's shaders (GENERATED by tools/port_shaders.py - do not edit)
    patched/           text-patched copies of a few desktop files (GENERATED by tools/patch_sources.py - do not edit)
    wwwroot/           index.html, main.js (boot, content download, input), gl.js (WebGL2 implementation), audio.js, host.js
  tools/               build + test scripts (below)
  vps/                 what runs on the server: setup_web.sh (nginx + HTTPS + websocket bridge), ws_bridge.py
  dist/                build output (site = interpreter build, site-aot = the fast one)
```

## Build
```
python tools/build_web.py            # interpreter build (slow startup, no extra tools needed)  -> dist/site
python tools/build_web.py --aot      # ahead-of-time build (10 s startup, 60 fps)                -> dist/site-aot
```
`--aot` needs the `wasm-tools` workload, installed into a user-local SDK at `%USERPROFILE%\.dotnet-wasm` (no admin rights):
`dotnet-install.ps1 -Version 10.0.400 -InstallDir %USERPROFILE%\.dotnet-wasm`, then `%USERPROFILE%\.dotnet-wasm\dotnet.exe workload install wasm-tools`.
The game content (art, fonts, xml) comes from the desktop client's built `Content` folder, so build the desktop client first.

If a desktop source that has a patch rule changes upstream, `patch_sources.py` stops with `PATCH FAILED` instead of silently building the old code -
update the rule in `tools/patch_sources.py` / `tools/patch_rules_more.py`.

## Try it locally
```
python tools/serve.py 8126 --aot                    # serves dist/site-aot, proxies /api to the VPS account server
python tools/ws_bridge.py 8125                      # local WebSocket -> game server bridge (the VPS one does this in production)
# open  http://127.0.0.1:8126/?game=ws://127.0.0.1:8125
```
Headless tests (Chrome via Playwright): `python tools/webtest.py URL --wait 60 --actions tools/acts_enter.json --shot out.png` (set `WT_GPU=1` for the real GPU,
`WT_NET=1` to log /api requests). `tools/shadercheck.py` compiles every ported shader in WebGL2.

## Put it online (the VPS)
1. DNS: an `A` record `play` -> `104.152.50.196` for warriorsandwizards.com (DNS only / grey cloud), so `play.warriorsandwizards.com` reaches the VPS.
2. `.\deploy.ps1 -SetupWeb` (once): installs nginx + a Let's Encrypt certificate + the websocket bridge service on the VPS.
3. `.\deploy.ps1 -Web` (every update): builds the AOT site and uploads it to `/var/www/warriors`.

Everything the browser talks to is on that one origin: `/` static files, `/api/` -> account server (:8080), `/game` -> websocket bridge -> game server (:2050, unchanged).
